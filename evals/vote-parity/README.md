# Vote-gate parity evidence (#348 / #328 Inc3)

Empirical evidence for whether kernloop's **native `gate vote @7`** is adversarially
on par with the external nexus **`consensus_vote @7`** scaffold — the precondition for
ever promoting the native gate to an enforce-tier ratifier (#328 Inc3). The criteria
are **human-ratified v2** (see #348, 2026-06-19); `scripts/vote-parity-check.mjs`
(`pnpm vote-parity`) is their executable, tamper-evident form.

## What this is NOT

It is **not** a promotion mechanism. Meeting the window earns _consideration_, never
"proven safe" (zero false-approves over 20 only bounds the true rate to ~14% at 95%
confidence). The #328 Inc3 promotion is a **separate human-ratified step** with an
**external** panel; the external check + the human merge + the standing canary stay in
the loop **permanently** (the native gate is necessary-not-sufficient for ratifying
protected-path / spec / tier decisions).

## ledger.jsonl

One JSON object per **paired data point** (native vs external on the _same_ fresh,
ratification-class proposal):

| field                    | meaning                                                                                  |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| `id`, `date`, `proposal` | the data point + the proposal it judged                                                  |
| `decisionType`           | `contract` \| `claims-semantics` \| `tier` \| `scope` (diversity ≥4 required)            |
| `native` / `external`    | `{ disposition: 'approve'\|'reject', approve?, reject? }`                                |
| `independenceVerified`   | native + external drew on genuinely independent model families                           |
| `organic`                | a real backlog proposal (not a synthetic injected adversarial)                           |
| `externalDangerous`      | the external panel **rejected or split** (a dangerous case; ≥5 needed, majority organic) |
| `counted`                | counts toward the formal `windowN` (only with `independenceVerified`)                    |
| `note`                   | free text                                                                                |

A data point is **counted** only when `independenceVerified && counted` — so the
pre-criteria DP#1–3 (gathered before v2, independence unverified) are **provisional**:
real reasoning-parity evidence, but they do not inflate the formal window
(pre-registration / no teach-to-the-test).

## Generating a data point (live)

DPs require real model votes, so they are generated by hand, not in CI:

1. Pick a fresh, ratification-class proposal from the real backlog.
2. Convene the native panel `@7` and `consensus_vote @7` on the **same** proposal, and
   record both panels' served model families.
   - The independence precondition is that the native panel and `consensus_vote` draw on
     **disjoint** families — NOT that the native panel is internally diverse. So a
     **single-model** native panel on a disjoint family qualifies: run
     `kernloop gate vote --panel 7 --adapter agy` (7 roles on google) — independent from
     `consensus_vote`'s {anthropic, openai}. (Internal native diversity is opt-in for vote
     QUALITY since #468 — the #461 experiment found roles, not model brand, carry the
     signal — and is NOT required for independence-from-external here.)
3. **Verify independence** before flagging `counted`: the native panel and
   `consensus_vote` must not share their model families, else "agreement" measures
   correlation. Append the record to `ledger.jsonl`; cross-link the #348 comment.
4. `pnpm vote-parity` re-scores the window. The committed ledger must always have
   **zero false-approves** in the counted window (a false-approve resets it, §2).

## Accrual is UNBLOCKED — single-model agy is independent (was #459, dissolved)

`consensus_vote` runs on **{anthropic, openai}**; the native adapter on a **disjoint**
family is **agy (google)**. The earlier "blocked" framing conflated _diverse native
panel_ with _independent from external_: it assumed a counted DP needed a provider-DIVERSE
native panel and that one disjoint family couldn't form one. But since #468 made native
diversity opt-in, a **single-model agy panel-7** (7 roles on google) is a valid native gate
AND is independent from `consensus_vote` — so **counted DPs are obtainable now, with no 2nd
adapter and no criterion change**. DP4 (2026-06-26) is the first: `kernloop gate vote
--panel 7 --adapter agy` vs `consensus_vote`, independence-verified. (Notably it was a
genuine model-DISAGREEMENT — the native gate rejected a proposal the external panel
split-approved — which #461 could not produce; independence turned out to MATTER, so the
precondition stays a HARD gate. See #459/#480-adjacent discussion.)
